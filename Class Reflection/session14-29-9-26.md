## Class reflection

## Application Testing

The focus of this session was primarily to ensure that the features built in the previous sessions were functioning as expected and that the completed application was correct. Rather than testing the features individually, we tested the application as a whole user.

We tested the splash screen, loading messages, progress bar and last opened-time. We also checked if the app was correctly transferring from the Splash screen to the Main notes screen.

## Testing the Notes Features

We tested the saving feature by creating and saving notes, and reopening the app to verify that the saved notes were loaded correctly.

The other key element of testing was the unsaved-changes alert. Without saving, we modified notes and determined if the application warned before closing. This helped us make sure that the user would have a chance to avoid accidentally losing their work.

## Complete Application Flow

We also conducted the full process of the app from opening to closing. This involved access to the splash screen, the main screen, creation of notes and editing, saving, reopening and closing the app.

The full flow test was used to determine if the various features were connected together or not.

## Presentation Preparation

Once the major testing was done, we began to create the PPT to present the project. We took screenshots that were able to clearly show the various features of the app and chose the key points of the project to explain.

We also began to structure the explanation around the objective of the project, its main features, FXML implementation and overall working of the application.

## What I Learned

In this session, I gained an appreciation for how to test an application from the user's perspective. A feature can be correct if it's tested alone, but it is important to verify that it is correct when used with the other features.

I also discovered that when making a presentation, one must choose what is most relevant to the presentation, rather than displaying all the small details of the development. Screenshots can make the explanation of the application's working much clearer.

## Challenges I Faced

A challenge was to ensure that the full application flow was smooth and uninterrupted. We needed to test a few things at the same time, and also ensure that we were getting a smooth flow of different aspects of the application.

Another difficulty was to select the screenshots and features that would be most helpful for the presentation; we wanted to present the project in a clear manner without making the presentation needlessly cluttered.

## Reflection

This session was a chance to view the project as a whole application rather than as merely individual pieces of code. The full flow test provided insight into the effectiveness of the features that we developed in the previous sessions.

I began preparing the PPT and began to think of the project from the explanation point of view. We needed to get a handle on the goal, features, structure of the FXML, and how it works sufficiently to be able to communicate that to other people. As a whole, it was a good preparation for both the application and ourselves to make a final presentation.

## Key Takeaways

After multiple features, it's crucial to complete application testing.
User perspective testing of saving, reopening and unsaved-change handling should be performed.
All flow must be tested from start to end.
