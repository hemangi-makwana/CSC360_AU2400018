## Professional GitHub Repositories

I learnt the importance of having a well structured GitHub repository. I learnt that the code should be structured in a way that other people can easily understand and implement.

I learnt about the important files we have to include in our GitHub repos such as README, pom.xml & .gitignore. README is the file that tells us what our project is, what features it has and the steps needed to run it. pom.xml is the file that handles dependencies and builds for our project. .gitignore is a file to ensure we don’t upload unnecessary files.

I learnt that having a well organised source code, test files and resources will help make maintenance easier. We shouldn’t upload any unecessary files that have been generated or any sensitive information.

I learnt that having a professional repo shows the quality of our development. In future projects I will aim to keep my repos well organised and include clear information.

## Javadoc

Another important topic was Javadoc. This is used to document Java classes and methods. I learnt that having proper documentation will tell you what your method does, what information it requires, what it returns and any possible errors.

We discussed the different tags that can be used to document our methods. This will tell us what parameters we have, what the method returns, any exceptions and what other classes/methods relate to it.

I learnt that README files are for general information about the project whilst Javadoc is for specific information about the Java code.

This has shown me that as a programmer I am not just responsible for writing code but making sure it can be understood by others. Having good documentation will help save time, reduce confusion and make it easier to work with others.

I will aim to write clearer comments in my future programming assignments and document any important methods.



## ImageJ

We learnt about ImageJ which is a Java based platform for analysing and processing images. We learnt about two key classes: ImagePlus and ImageProcessor.

ImagePlus is responsible for handling the image as a whole. It will store information such as the title, size and other related information. ImageProcessor is more focused on the pixel data.

We also discussed different ImageProcessor classes. These can be used for different types of images such as black and white and colour images.

This was helpful as it showed me how complex tasks can be split across multiple classes. ImageJ will have separate components for handling the image information and pixel data.

This helped me understand how using object orientated programming can help make our software more organised. When creating my own Java applications I can use this concept to give each class specific responsibilities.



## Conventional Commits & Semantic Versioning



During this session we learnt about how we can organise changes to our projects as a developer. I learnt that we should clearly state what has been changed in our commit messages.

We discussed Conventional Commits. This uses standardised categories for our changes. For example if we are adding new features we will use a feature commit message. If we are fixing a bug we will use a fix commit message. If we are changing the documentation we will use a documentation commit message.

I also learnt about Semantic Versioning. This helps us to understand how important our changes are between versions of software. Major versions indicate breaking changes. Minor versions are new features that won’t break existing behaviour. Patch versions usually contain bug fixes.

This has helped me realise that version control isn’t just about pushing our code onto GitHub. It helps us keep a clear history of our development and makes it easier for team members to understand our changes.

I will aim to write more descriptive commit messages and keep my changes organised.



## Image Sampling, Quantization & Coordinates



Another concept I learnt about was how digital images are represented in a computer. I learnt that digital images are made up of pixels. Each pixel holds information about the image.

Sampling is used to determine where the pixels will be placed. Quantisation determines the intensity values. The amount of intensity values depends on how many bits the image has.

We also discussed the coordinate system used in digital images. Unlike the standard mathematical coordinate system the coordinates usually start from the top left hand side. The x value will increase going to the right and the y value will increase going down.

I learnt that pixel data can be stored as a 1D array in the computer’s memory. This is important to know when trying to access individual pixels or to implement image processing.

This has helped me understand how visual information relates to how data is stored in a computer. It has also shown me how we need to be careful when handling image sizes and pixel locations to prevent any errors.



## Java Testing



Another important aspect of this session was testing. I learnt that we should test our code throughout our development.

We discussed unit testing, integration testing and system testing. Unit testing is where we test individual parts of our program. Integration testing is where we test how the components work together. System testing is where we test the whole application.

We also learnt about the arrange act assert method. This is where we set up our test, we perform the action and then we check to see if the outcome was correct. JUnit is a popular framework for writing automated tests in Java.

Automated testing helps us find errors earlier. It also reduces the chance of previous issues coming back after changes have been made. It gives developers more confidence when improving/ re structuring their applications.

I realised that sometimes it isn’t enough to check if our program works manually. By writing the correct test cases our development will be more reliable.

I want to improve my testing skills in future projects.



## Adding ImageJ with Maven

We learnt how to add external libraries to our Java projects using Maven. This means we don’t have to manually download and configure the files. Instead we can state our dependencies in our configuration file.

We can add ImageJ as a dependency to our Maven project. This means we can use the classes and methods in our Java code.

This makes setting up our project easier. As Maven will handle the libraries for us it makes it easier for different developers to have a consistent environment. It also makes it easier to build and test our project on different computers.

We can use ImageJ in our project to open images, get pixel data, perform transformations and save the results.

This helped me understand how external libraries can be used to increase the capabilities of a programming language. It also showed me the importance of managing dependencies.
